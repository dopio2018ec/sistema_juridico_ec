
# PROMPT MAESTRO PARA CLAUDE CODE
## Desarrollo de un sistema de gestión jurídica del Ecuador

Actúa como un **arquitecto de software senior, analista de sistemas y especialista en seguridad de aplicaciones web PHP**. Debes diseñar e implementar una aplicación web profesional para administrar legislación ecuatoriana, utilizando PHP y MariaDB.

No te limites a generar ejemplos o fragmentos de código. Trabaja sobre el proyecto, crea los archivos necesarios, implementa las funcionalidades, ejecuta las pruebas disponibles y documenta cómo instalar y mantener la aplicación.

## 1. Objetivo del proyecto

Construir un sistema web denominado **Sistema Jurídico Ecuador**, que permita registrar, organizar, consultar, buscar y actualizar normas jurídicas y sus artículos, conservando únicamente el texto vigente de cada artículo.

El sistema debe permitir gestionar:

- Constitución de la República del Ecuador.
- Códigos.
- Leyes orgánicas.
- Leyes ordinarias.
- Acuerdos ministeriales.
- Resoluciones.
- Otros tipos de normas configurables.

El sistema debe estar preparado para ampliarse posteriormente con nuevas categorías, funcionalidades y módulos.

## 2. Tecnologías obligatorias

Utiliza las siguientes tecnologías:

- **Backend:** PHP 8.3 o superior, compatible con una versión estable soportada.
- **Base de datos:** MariaDB 10.11 o superior, o una versión estable compatible.
- **Acceso a datos:** PDO con consultas preparadas.
- **Frontend:** HTML5, CSS3, JavaScript y Bootstrap 5.
- **Iconografía:** Bootstrap Icons.
- **Arquitectura:** MVC o una estructura por capas claramente separadas.
- **Control de versiones:** Git.
- **Pruebas:** PHPUnit para pruebas unitarias y de integración cuando corresponda.

Evita dependencias innecesarias. Si propones Composer, utiliza paquetes conocidos, mantenidos y compatibles con las versiones seleccionadas.

No mezcles consultas SQL, lógica de negocio y presentación en un único archivo PHP.

Antes de implementar el código, inspecciona el esquema SQL existente si está disponible en el proyecto. Respeta sus nombres, tipos de datos, claves foráneas e índices.

No elimines ni renombres columnas existentes sin justificar el cambio y proporcionar una migración compatible.

### Reglas del modelo jurídico

1. Cada norma pertenece a un tipo de norma.
2. Una norma puede contener múltiples artículos y disposiciones.
3. Cada artículo debe almacenar directamente su contenido vigente.
4. No implementar tablas de versiones históricas de artículos ni reconstrucción de textos anteriores.
5. Una norma puede tener múltiples publicaciones oficiales.
6. Una norma puede reformar o derogar otra norma, total o parcialmente.
7. Los artículos pueden representar considerandos, artículos numerados y disposiciones generales, transitorias, reformatorias, derogatorias y finales.
8. Cada artículo debe tener un número o identificador, título opcional, contenido, orden y fechas de creación y actualización.
9. Las modificaciones deben registrar el usuario responsable.
10. No eliminar físicamente registros jurídicos de manera rutinaria; utilizar estados y restricciones de integridad.

Los cambios al texto vigente deben efectuarse mediante transacciones cuando involucren varias operaciones relacionadas.

La aplicación no debe afirmar que una norma está vigente únicamente porque su estado sea `VIGENTE`. Debe considerar las fechas, las relaciones normativas y la información de las fuentes oficiales. Cuando no exista información suficiente, debe indicar que la vigencia está pendiente de verificación.

## 5. Autenticación y gestión de usuarios

Implementa un módulo completo de usuarios.

### Funcionalidades

- Inicio y cierre de sesión.
- Creación de usuarios por un administrador.
- Edición de datos personales.
- Activación y desactivación de cuentas.
- Asignación de uno o varios roles.
- Cambio y restablecimiento seguro de contraseña.
- Consulta de usuarios con paginación.
- Búsqueda por nombre, correo y estado.
- Registro de último acceso, si se incorpora el campo correspondiente.
- Bloqueo temporal ante múltiples intentos fallidos.
- Revocación de sesiones activas cuando sea necesario.

### Seguridad de contraseñas

Utiliza `password_hash()` con Argon2id cuando esté disponible y correctamente configurado, o `PASSWORD_DEFAULT` como alternativa.

Verifica las contraseñas con `password_verify()` y permite actualizarlas mediante `password_needs_rehash()`.

Nunca almacenes contraseñas en texto plano ni utilices cifrado reversible para ellas.

### Roles y permisos

Implementa como mínimo estos roles:

- `ADMINISTRADOR`: administra usuarios, roles, catálogos y configuración.
- `EDITOR_JURIDICO`: registra y actualiza normas, publicaciones y artículos.
- `REVISOR`: revisa y valida información jurídica.
- `CONSULTA`: accede únicamente a las funcionalidades de lectura permitidas.

Los permisos deben verificarse en el backend mediante middleware o políticas de autorización. Ocultar botones en la interfaz no constituye un control de acceso.

Aplica el principio de mínimo privilegio.

## 6. Sesiones, tokens de acceso y CSRF

Distingue correctamente los mecanismos de seguridad:

### Para la aplicación web

- Utiliza sesiones PHP seguras.
- Activa `session.use_strict_mode`.
- Configura cookies `HttpOnly`, `Secure` bajo HTTPS y `SameSite=Lax` o una política más estricta compatible con la aplicación.
- Regenera el identificador de sesión después del inicio de sesión y los cambios de privilegios.
- Establece tiempos de expiración por inactividad y duración máxima de sesión.
- Invalida correctamente la sesión en el cierre de sesión.
- Protege formularios y solicitudes que modifican datos mediante tokens CSRF generados criptográficamente.
- Verifica los tokens CSRF en el servidor mediante comparación segura.
- No utilices tokens CSRF como sustituto de la autenticación o autorización.

### Si se implementa una API

Crea un módulo independiente de autenticación para API, con:

- Tokens de acceso aleatorios y criptográficamente seguros.
- Expiración configurable y duración limitada.
- Revocación de tokens.
- Alcances o permisos asociados a cada token.
- Almacenamiento de hashes de tokens, cuando el diseño lo permita.
- Validación del token en cada solicitud protegida.
- Transporte exclusivo mediante HTTPS.
- Prohibición de incluir tokens en URLs, logs o mensajes de error.

No inventes un sistema criptográfico propio ni implementes JWT si no existe una necesidad concreta. Si se elige JWT, valida estrictamente el algoritmo, emisor, audiencia, expiración y demás claims requeridos.

La API debe estar deshabilitada si no forma parte de la primera versión funcional.

## 7. Seguridad de consultas y validación de datos

### Consultas preparadas

Utiliza PDO y consultas preparadas para todas las operaciones SQL que incluyan datos variables.

Ejemplo de referencia:

```php
$stmt = $pdo->prepare(
    'SELECT id, nombre, correo
     FROM usuarios
     WHERE correo = :correo
       AND estado = 1'
);

$stmt->execute([
    'correo' => $correo
]);

$usuario = $stmt->fetch(PDO::FETCH_ASSOC);
```

Configura PDO para lanzar excepciones ante errores y utiliza el modo de emulación de consultas preparadas desactivado cuando sea compatible.

No concatenes valores proporcionados por usuarios en sentencias SQL.

Para ordenamientos y nombres de columnas dinámicos, utiliza listas permitidas explícitas, porque los identificadores SQL no se protegen igual que los valores parametrizados.

### Validación de entradas

Implementa validaciones del lado del servidor para todos los formularios y solicitudes.

Valida, según corresponda:

- Campos obligatorios.
- Longitudes máximas y mínimas.
- Formato del correo electrónico.
- Unicidad del correo.
- Fechas válidas y coherentes.
- Identificadores numéricos positivos.
- Existencia de las claves foráneas.
- Valores permitidos para estados, roles y tipos de norma.
- Longitud de títulos, números de norma y nombres de instituciones.
- Formato y protocolo de las URL de fuentes oficiales.
- Tipos y tamaños de archivos si se habilitan adjuntos.
- Permisos del usuario sobre el recurso solicitado.

No confíes en validaciones JavaScript como única protección.

### Protección adicional

Implementa:

- Prevención de inyección SQL.
- Prevención de XSS mediante escape contextual de salida.
- Protección CSRF.
- Prevención de IDOR mediante autorización sobre cada recurso.
- Limitación de intentos de autenticación.
- Control de errores sin revelar consultas, rutas ni credenciales.
- Encabezados de seguridad HTTP.
- Política de seguridad de contenido (CSP), ajustada a las dependencias utilizadas.
- Restricciones de carga de archivos, si existe esa funcionalidad.
- Protección contra asignación masiva de campos.
- Logs de seguridad sin contraseñas, tokens ni datos sensibles.
- HTTPS obligatorio en producción.

No deshabilites globalmente errores para ocultar problemas durante el desarrollo. Configura la visualización de errores por entorno y registra los detalles técnicos en logs protegidos.

## 13. Recomendaciones adicionales

Evalúa e implementa cuando sea pertinente:

1. **Copias de seguridad automáticas:** respaldo de MariaDB, retención definida y pruebas periódicas de restauración.
2. **Confirmación de cambios jurídicos:** solicitar una segunda revisión antes de publicar contenido modificado, con una marca de validación y el usuario revisor.
3. **Verificación de fuentes:** registrar referencias documentales y permitir señalar si una fuente está pendiente de comprobar.
4. **Importación de documentos:** permitir cargar archivos PDF como documentos de referencia, con límites de tamaño, validación MIME y almacenamiento fuera del directorio público.
5. **Exportación:** generar reportes PDF o Excel con información autorizada y referencias a las fuentes.
6. **Control de concurrencia:** evitar que dos editores sobrescriban accidentalmente los cambios recientes de otro usuario.
7. **Accesibilidad:** cumplir buenas prácticas WCAG y permitir navegación con teclado.
8. **Observabilidad:** logs estructurados, seguimiento de errores y alertas para fallos críticos.
9. **Privacidad:** recolectar únicamente los datos personales necesarios y definir una política de retención.
10. **Preparación para crecimiento:** diseñar servicios y repositorios reutilizables, índices adecuados y paginación eficiente.

Las funcionalidades adicionales deben priorizarse por etapas, sin comprometer la seguridad ni la calidad del núcleo de la aplicación.
